# Tuna Desktop v1 — definition and victory checklist

Authority: the v1 definition spec (`20261009134949-7190f8bf-tuna-desktop-v1-definition`),
as amended by [ADR 0008](adr/0008-v1-beta-track-and-release-scope.md).
This page mirrors its checklist; where they disagree, the spec and ADR win.

## The bar

v1 means a desktop you can switch to without losing anything GNOME 51
does, and that feels faster while doing it: every tracked capability
verified working, no known gaps left open, and responsiveness
measurably quicker than GNOME on the same machine while using no more
CPU. Baseline is GNOME 51 as shipped in the Marlin GNOME image, on
identical hardware and the same image family.

Performance means: beat GNOME on responsiveness (overview opens,
input reaction, animations) and match it on CPU and memory. GPU-aware
cost accounting and total-power comparison were waived for v1 by the
owner on 2026-10-13 and remain a follow-up.

## Victory checklist

- [ ] Every tracked capability verifies as passing (parity checklist
  all green, each with its proof linked).
- [ ] No known gaps remain open (open gap list empty; latest audit
  finds nothing untracked).
- [ ] Daily work needs no GNOME fallback (launch, switch, notify,
  configure, lock — entirely in Tuna).
- [ ] Responsiveness beats GNOME 51 on identical hardware
  (published benchmarks).
- [ ] Resource use matches GNOME 51 (CPU, memory).
- Waived for v1, follow-up: power comparison, and methodology that
  records CPU and GPU cost separately with total power on every run.
- [ ] Shipped Marlin image flavor qualifies end to end (install,
  boot, real-greeter login, passing qualification run).
- [ ] Release safety nets hold (recovery without data loss, proven
  upgrade path).
- [ ] Every TunaOS variant ships a qualified Tuna flavor (install,
  real-greeter login, session, portals, lock/unlock per image digest),
  or is published as unsupported with a recorded reason (ADR 0008).
  Current inventory, immutable subjects and gate limits:
  [variant qualification matrix](v1-variant-qualification.md).
- [ ] This list stays public and current — one click from the front
  page, readable without asking anyone.

## Where the evidence lives

- Capability tracking: `docs/parity-ledger.md`. The nightly
  `victory-checks` signal counts every ledger row by status; only
  `pass` counts toward the pass fraction, `pass (nested)` rows count
  toward the total until they pass outside the nested session.
- Gap issues: `[GNOME 51 gap]` label on GitHub.
- Benchmarks: the published performance lanes and nightly gate.
- Image qualification: Marlin flavor lanes and the published-flavor
  nightly.
- Program order and gates: `docs/roadmap.md`.

## Betas before v1

`v1.0.0-beta.N` prereleases ship from `main` while this list is still
open ([ADR 0008](adr/0008-v1-beta-track-and-release-scope.md),
[release runbook](release.md#prereleases-betas-and-release-candidates)).
Every beta lists its open rows as known limitations and claims no item
above.

## Non-goals

Extension broker and public API stay post-1.0 unless explicitly
promoted; nothing in v1 depends on them.
