# Tuna Desktop 1.0.0-beta.3

Third prerelease of Tuna Desktop: a Wayland desktop built on Smithay with a GTK 4 shell, aiming to match GNOME 51 as shipped in TunaOS Marlin. Package versions: Debian `1.0.0~beta.3`, Arch `1.0.0beta.3`; `--version` reports `1.0.0-beta.3`. This is a beta. It does not claim the [v1 gates](../v1.md) or the [roadmap release gates](../roadmap.md#global-decision-gates). Beta scope is set by [ADR 0008](../adr/0008-v1-beta-track-and-release-scope.md).

This beta exists mainly so that the published `marlin:tuna` image can pick up fixes that merged after the beta.2 tag ([#1044](https://github.com/tuna-os/tuna-desktop/issues/1044)). At publication the image still carries `tuna-desktop 1.0.0beta.2-2`; it changes when TunaOS rebuilds the package and the image from this tag.

## Changes

Covers `main` from `v1.0.0-beta.2` (`1e6ce28`, 2026-10-29) to `9062bc5` (#1099, 2026-11-13 UTC). The tagged commit adds only these notes, the visual review and the version stamp to that source. Changes merged to `main` after `9062bc5`, including the fixes for #1077 (#1085) and #1104 (#1105), are not in this beta.

### Fixed since the published beta.2 image
- `notify-send` and other libnotify clients work: the notification service answers `GetServerInformation` (#850, issue #843).
- Locking sets the logind `LockedHint`, and `loginctl lock-session` / `unlock-session` are honoured (#849, issue #846).
- The Dark Style and Night Light quick-settings tiles follow changes made elsewhere, opening a toggle menu no longer makes the whole quick-settings popover translucent, and banners hide while the date menu is open (#850, issues #844, #847, #845).
- Power menu Log Out reaches the compositor again (#873).
- The polkit agent uses polkit's helper socket (polkit 127 and later) instead of respawning its helper (#906).
- X11 input focus follows the focused X11 window (#909); the pointer focus is re-picked when a window maps or the scene changes under a stationary pointer (#941); a drag-and-drop target is established when the pointer grab starts (#959).
- The compositor no longer waits on the session bus from its event loop (#878), and fd-exhaustion and fuzz-found crashes are fixed (#907).

### Removed
- The greetd greeter (`tuna-greeter`) and the greetd unlock route. Login is through GDM only (#866). The package now ships six binaries.

### Window management and input
- Clipboard contents stay pasteable after the copying app closes, as in Mutter 51 (P-SY-11, #1056).
- A window that stops responding gets GNOME 51's "not responding" dialog with Force Quit and Wait (P-WM-11, #1060).
- Opt-in window session restore through `xdg_session_manager_v1`, as Mutter 51 (P-SY-08, #840).
- GNOME 51 touchpad swipe recognition through libinput; the overview swipe reaches the app grid, workspaces follow the fingers, and right-to-left layouts flip (#901). Activities dots and the workspace popup follow swipes (#888).
- Graphics tablets, pads and GNOME Wacom settings (P-IN-05, #861).
- Monitor hotplug follows DRM connectors as Mutter does, and windows are re-homed when outputs change (#892).
- Pointer motion is coalesced per output frame (#927).
- Screenshot UI keyboard selection uses GNOME 51's exact modifiers (P-SY-10, #922).
- Running apps are activated as GNOME 51's `AppIcon.activate` does (#916).
- Protocols: security-context, idle-notify, content-type, foreign-toplevel-list and alpha-modifier; layer shell is limited to the shell (#1057). `org.gnome.Mutter.InputCapture` backs the InputCapture portal (P-SY-13, #1062).

### Accessibility
- GNOME 51 on-screen keyboard (P-A11Y-03, #839).
- Keyboard routes for panel menus, quick settings, notifications, the window menu and the screenshot UI (P-A11Y-02, #893).
- Orca speaks banners, the switcher and Activities; Super+Alt+S toggles it (P-A11Y-06, #864).
- Panel buttons mark keyboard focus with GNOME 51's fill instead of libadwaita's outline, and the accessibility menu keeps its state across a shell restart (#914).

### Shell, animations and settings
- Quick settings: Airplane Mode and keyboard backlight toggles (P-PN-05, #1053).
- System menu: Switch User (P-SY-12, #1055). End-session dialogs go through `org.gnome.SessionManager` with GNOME 51's dialog details (P-SY-07, #880, #958).
- Captive-portal sign-in for hotspot networks (P-ST-12, #1054); Thunderbolt device enrolment and notices (P-SY-14, #1058).
- AppIndicator tray host that behaves like the Ubuntu/Fedora extension (P-TR-01, #920).
- Lock screen: multi-step and fingerprint authentication (P-LK-02, #853); a touchpad swipe lifts the unlock curtain (P-AN-10, #895).
- Notifications use GNOME's one-banner message tray (#860).
- Colour management: colord devices, ICC profiles, VCGT calibration, and Night Light on the CRTC white point (P-DS-03, #854).
- Privacy screen support as in Mutter 51 (#890); removable-media automount and autorun (#889); Wellbeing screen-time and break notifications match GNOME 51 (#868).
- Date & Time: the panel clock follows time-zone changes (#886); the GeoClue agent for automatic time zone is admitted through the distribution's own policy (#1003).
- Remote desktop: gnome-remote-desktop is admitted, with keysym, clipboard and mapping-id handling as Mutter 51 (#891).
- Animations: popup submenus, the window menu and Alt+Tab image fades (#902).
- Wallpaper: a failed decode is never persisted as the fallback (#883), and content changes are detected beyond file timestamps (#960).
- `org.gnome.Shell.Introspect` is served on `org.gnome.Shell` for the Background portal (#908).

### Performance
- One GLES texture read fence per frame instead of one per drawn texture (#841).
- Damage under opaque windows is culled and the native loop idles between client frames (#869). On the local DRM replica described in that change, the compositor's settle CPU fell from 6.0% to 2.1-2.2% and idle from 0.40% to 0.27%; this is not a paired GNOME comparison.
- The notification history list is built only while it is shown (#838).
- The Marlin performance gate reports a bootstrap interval per metric and marks decisions inside run-to-run noise as unstable (#838); the reference base image is pinned by digest (#1070).

### Packaging, release and CI
- The `tuna-lock` PAM conffile has the beta.1 bytes again, so dpkg does not prompt on upgrade (#930).
- Published-image qualification is strict: no historical waivers (#994). The Marlin VM lane logs in through stock GDM like the published image (#858), and a Corral daily-driver journey walks the published flavor (#842).
- `try-tuna-desktop` fails fast on an unsigned image (#1029).
- A producer for a verified pristine VM disk with a signed manifest (`vm-release.yml`, #993). No launcher VM release has been cut.
- CI: self-hosted runners (#923), locked Actions and zizmor (#1067), timeouts on every job (#933).
- Toolchain kept current, most recently nightly-2026-11-12 (#1030).

Known bugs in this beta (as of 2026-11-13):
- X11 override-redirect windows (menus, tooltips, dropdowns of X11 apps) are not drawn ([#1076](https://github.com/tuna-os/tuna-desktop/issues/1076)).
- X11 windows without their own decorations get no server-side frame (P-WM-10, [#1034](https://github.com/tuna-os/tuna-desktop/issues/1034)); minimizing an X11 window does not update `WM_STATE` or `_NET_WM_STATE_HIDDEN` ([#1078](https://github.com/tuna-os/tuna-desktop/issues/1078)).
- Native windows cannot be resized from the invisible border in their shadow ([#1079](https://github.com/tuna-os/tuna-desktop/issues/1079)).
- The compositor panics when every output is unplugged during the overview's close animation ([#1104](https://github.com/tuna-os/tuna-desktop/issues/1104)). Fixed on `main` after this beta's source (#1105).
- Memory grows over time: about 1.65 MB per closed window in the compositor ([#1088](https://github.com/tuna-os/tuna-desktop/issues/1088)), a shm pool and a file descriptor per search that shows results ([#1084](https://github.com/tuna-os/tuna-desktop/issues/1084)), and 1-2.5 MiB per monitor hotplug round ([#1101](https://github.com/tuna-os/tuna-desktop/issues/1101)).
- `tuna-shell-gtk` exits when its accessibility tree is read while the window menu is closing ([#1077](https://github.com/tuna-os/tuna-desktop/issues/1077)). Fixed on `main` after this beta's source (#1085).
- Two `ibus-daemon` processes can race at login ([#1014](https://github.com/tuna-os/tuna-desktop/issues/1014)).
- Keys held when the lock engages may reach the session after unlock ([#939](https://github.com/tuna-os/tuna-desktop/issues/939)); Orca does not hear lock-screen keys ([#936](https://github.com/tuna-os/tuna-desktop/issues/936)).
- The calendar popover has no World Clocks or Weather (P-PN-04, [#1036](https://github.com/tuna-os/tuna-desktop/issues/1036)) and the notification list has no media player controls (P-NT-04, [#1037](https://github.com/tuna-os/tuna-desktop/issues/1037)).
- The DRM backend has no KMS cursor plane, direct scanout, overlay planes, VRR, tearing control or formats above 8 bits ([#1045](https://github.com/tuna-os/tuna-desktop/issues/1045)).

Open v1 gates (`docs/v1.md`), all unchecked for this beta:
- Not every tracked capability passes (rows above).
- Known gaps remain open (`[GNOME 51 gap]` issues).
- Daily work without any GNOME fallback is not yet proven.
- Responsiveness beating GNOME 51 on identical hardware is not yet shown across the board.
- Resource use matching GNOME 51 is not met. That is the open v1 performance gate ([#503](https://github.com/tuna-os/tuna-desktop/issues/503)).
- The shipped Marlin image flavor is not yet qualified end to end on hardware (install, boot, real-greeter login, qualification run). The published image carried beta.2 when this beta was tagged; its strict nightly qualification and the Corral daily-driver journey have to be re-run on the digest that carries beta.3 ([#1044](https://github.com/tuna-os/tuna-desktop/issues/1044)).
- Release safety nets (recovery without data loss, proven upgrade path) are not yet proven. The upgrade mechanisms are recorded in `docs/legacy-upgrade.md`, with native qualification gaps listed there.
- Not every TunaOS variant ships a qualified Tuna flavor ([variant matrix](../v1-variant-qualification.md), [#1050](https://github.com/tuna-os/tuna-desktop/issues/1050)).
- The public v1 checklist is not yet one click from the front page.

Performance gate status:
- The Marlin performance-sample budget gate is still intermittent ([#782](https://github.com/tuna-os/tuna-desktop/issues/782)). Since #838 it marks decisions whose interval straddles the budget as unstable instead of failing or passing on noise.
- No paired CPU figures are claimed for this beta. The performance lane measured nothing between Arch's openssl 4 transition and #1070 (merged 2026-11-12). A paired [Marlin performance samples run](https://github.com/tuna-os/tuna-desktop/actions/runs/43392789272) completed on 2026-11-13 on a later `main` commit (`6a58166`, which includes #1085 and #1105); it measures a candidate build, not this release.
- The 24-hour endurance soak of 2026-10-31 failed and is not qualified (`docs/soak/2026-10-31-24h/README.md`); the nightly attaches a bounded 50-minute soak, which is not 24-hour evidence (#882).
- GPU and total-power comparisons stay waived for v1 (owner decision 2026-10-13).

Also:
- No physical-hardware qualification for any target ([#1049](https://github.com/tuna-os/tuna-desktop/issues/1049)).
- Visual review: `docs/reviews/v1.0.0-beta.3.md`. The baseline and frame gaps from beta.1 (#672) remain: the GNOME 51 bundle still has no notification-banner stage and no usable lock frames.

## Supported configurations
- TunaOS Marlin (Arch-based bootc), x86_64, via the `marlin:tuna` image. The image carries this beta only after TunaOS rebuilds it from the `v1.0.0-beta.3` tag (#1044).
- Ubuntu 26.04 (amd64), `.deb` package. Debian 13 is not supported yet: it needs a packaged gtk4-layer-shell >= 1.1 backport and a separately qualified artifact. Neither target has physical-hardware qualification.

## Upgrade and uninstall
- Upgrading the beta.2 `.deb` removes `/usr/bin/tuna-greeter`; sessions start from GDM. Removing the package keeps user configuration and application data. The upgrade mechanisms and their open native qualification gaps are in the [legacy-upgrade guide](../legacy-upgrade.md).

## Checksums

The `.deb` is built by the tag's `ci` run (`tuna-deb` artifact) and attached to the GitHub release with its SHA-256.
