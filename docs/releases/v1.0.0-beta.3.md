# Tuna Desktop 1.0.0-beta.3

Limited beta release candidate for Tuna Desktop, a Smithay Wayland compositor with a GTK 4 shell targeting GNOME 51 functionality. This is not v1 completion, closure of [release epic #577](https://github.com/tuna-os/tuna-desktop/issues/577), or a claim that the [v1 checklist](../v1.md) or [roadmap global gates](../roadmap.md#global-decision-gates) pass.

## Source boundary and release status

The owner authorized this limited bootstrap on `release/beta3-bootstrap` from **`d65e35f27237576c6708978cb8be6c0d9e048768`**, not from latest `main`. This is an explicit branch-source exception to the usual main-based beta procedure in [ADR 0008](../adr/0008-v1-beta-track-and-release-scope.md) and the [release runbook](../release.md), not a waiver of qualification or publication requirements.

The branch also carries the causal published-image fixture repair for [#990](https://github.com/tuna-os/tuna-desktop/issues/990): `e6eda002102a27086e15ea855361749047a801c0` (backport of `2885d287eeb40b6ff449f2226788ea70fa90539e`) and its fixture-test anchoring correction `e1804dd66bad429dbbc16bf4998740fd36fe04fc` (backport of `a4eaf0a83ab1c19e52e044fa52c2182b919c6c17`). Fixture packages resolve against the published image's own package databases, with the Arch Linux Archive as fallback for snapshot files. This prevents an incidental `pacman -Sy` upgrade from changing the shipped payload during qualification; the shipped-package version gate remains enforced. It is a qualification installer fix, not evidence that the image or desktop passed.

These notes do not establish a tag, published release, completed build, package checksum, image digest, or passing beta.3 run. The intended version identifiers are `1.0.0-beta.3` for binaries, `1.0.0~beta.3` for Debian packaging, and `1.0.0beta.3` for Arch packaging. Actual artifact versions and provenance must be checked before publication.

## Changes from beta.2

The source change boundary is immutable tag `v1.0.0-beta.2` (`1e6ce28f4d5dfd7918ac7340bd93454a9fcc211c`) through the pinned `d65e35f2` base, plus the explicit fixture backports above and the candidate-version tooling described below. Selected implemented changes in that interval are listed here; implementation does not establish installed or hardware acceptance.

### Intended clock-monitor improvement

The panel clock's `/etc/localtime` monitor and Date & Time work from #886 (`414e358e`) are included. The intended improvement over the published beta.2-2 package is that the panel follows timezone changes rather than retaining its previous zone, including subsequent manual-time display. This is a clock/timezone monitor, not a multi-display or hotplug qualification claim.

The base's #971 change scopes two panel-follow proofs only for known obsolete published packages `1.0.0beta.1-1` and `1.0.0beta.2-2`, preserving their raw results. **Beta.3 receives no such exception**: timezone-follow and manual-time panel proofs, along with the other Date & Time gates, must pass on its installed payload. See [Date & Time proof requirements](../datetime-proof.md).

### Desktop, input and integration

- Window session restoration via `xdg_session_manager_v1` (#840); graphics tablets, pads and GNOME Wacom settings (#861).
- Colord devices, ICC profiles and VCGT calibration, with Night Light applied to the CRTC white point (#854); privacy-screen consumer work (#890). These do not qualify HDR, every colour path, or physical display hardware.
- On-screen keyboard (#839), multi-step/fingerprint lock authentication (#853), additional Orca announcements and screen-reader shortcut (#864), and accessibility-menu focus/restart proof work (#914). Complete native accessibility and authentication acceptance remains required.
- Logind lock hints and Lock/Unlock handling (#849); touchpad unlock-curtain behavior (#895); logout signaling (#873); polkit helper-socket integration (#906).
- Notification server/banner and quick-settings changes (#850), one-banner message-tray behavior (#860), wellbeing semantics (#868), removable-media automount/autorun (#889), Background portal introspection (#908), and additional submenu/window-menu/Alt+Tab fades (#902).
- X11 focus handling (#909), stationary-pointer repicking after scene changes (#941), and pointer-motion coalescing per output frame (#927).
- The greetd greeter and unlock route were removed (#866); graphical login uses stock GDM. Package contents and real GDM login must still be qualified for the new artifact.

### Performance and qualification infrastructure

- One GLES read fence per frame (#841), reproducible-performance-gate work (#838), damage culling and event-loop idling (#869), and removal of session-bus waits from the compositor event loop (#878).
- Corral daily-driver journey tooling (#842), stock-GDM VM login (#858), bounded memory/frame-pacing soak reporting (#882), bounded external waits (#934), and runner/cache/proof reliability changes through the pinned base.

These changes are not new paired CPU, latency, memory or endurance results. In particular, a bounded soak report is not the required 24-hour endurance run.

## Known limitations and open release gates

All v1 checklist items remain unclaimed by this limited beta:

- **Capabilities and gaps:** every tracked capability must verify as `pass`, with proof linked, and every known gap must be resolved or explicitly dispositioned. Nested-only and partial rows in the [parity ledger](../parity-ledger.md) are not native acceptance. #577 remains the canonical release/capability epic; Settings #367, Core apps #397, animations #492, and remaining portal/frontend/shipped-image acceptance #776 and RemoteDesktop #358 retain their separate acceptance requirements.
- **Daily-driver use:** daily work without a GNOME fallback is not established. Installed journeys must cover overview/workspaces/app-grid behavior, notifications, shortcuts/consent, IME caret behavior, live Settings interoperability, applications, configuration and lock/unlock. Old published-package regressions are not closed merely by including their source fixes.
- **Performance:** responsiveness beating GNOME 51 and CPU/memory parity on identical hardware remain open (#503, #315). Calibrated regression tooling (#547) and optimizations do not prove the outcome; retain variance/reproducibility evidence, including the #782 performance-gate investigation. Publish comparable fresh paired measurements and growth/frame-pacing evidence. GPU and total-power comparisons remain waived for v1, not CPU, memory or latency.
- **Endurance:** the actual 24-hour run and comparable performance work (#203, #73) remain required, recording exact binary/image provenance, resource growth, frame pacing and failures.
- **Marlin qualification:** the current package and signed amd64 Marlin flavor require clean installation, boot, real-greeter login, installed session controls, portals, PAM/lock and update/rollback qualification. Historical image admission (#69), an older beta's journey, a successful package build or a nested tour cannot qualify beta.3.
- **Other TunaOS variants:** each variant needs its own image-digest-linked install, real-greeter login, session, portals and lock/unlock results, or a published unsupported disposition and reason. Marlin remains the GNOME 51 comparison platform; one variant's evidence does not cover another.
- **Session and hardware:** real VM suspend/resume, VT switching, logout and fail-closed lock behavior (#62, #68), and a separate physical GPU/driver and mixed-display matrix remain required. Software-rendered VM results cannot establish hardware audio, backlight, gamma, hotplug or mixed-refresh support. No beta.3 physical-hardware qualification is claimed.
- **Upgrade and recovery:** prove recovery without data loss and the native upgrade path. The #780 mechanisms and closure of compatibility-removal issue #505 do not resolve the outstanding public upgrade review of #775. Preserve the exact transition allowance and settings; qualify real GDM remembered-name/reselection, old-compositor unlock, Arch replacement and Marlin activation/rollback as described in the [upgrade guide](../legacy-upgrade.md).
- **Qualification reliability:** retained intermittent proof/lifecycle investigations #747 and #748 require their own evidence. A green unrelated run or resolved earlier baseline incident does not establish their cause or closure.
- **Security:** end-to-end trusted identities and lock/auth/portal/capture authority require specialist review without unresolved critical issues, including production same-UID identity. No critical lock/capture/input/clipboard/IME/accessibility regression may remain. Document the compositor crash boundary and retain capture ownership, consent, revocation and locked-state proof. RustSec maintenance/soundness warnings still require policy-based triage.
- **Visual evidence and provenance:** complete the beta.3 visual review against a named GNOME 51 reference and retain exact-source installed frames/media; prior baseline/frame gaps (#672) and media provenance (#506) are not solved by these notes. The published Marlin reference recorded in the roadmap contained GNOME Shell 50.5, so GNOME 51 comparisons must identify the separately upgraded reference payload.
- **Public readiness:** the v1 checklist must remain public, current and one click from the front page; support/tester feedback and maintainer continuity remain tracked by #652. This document does not claim that public-readiness gate.

The roadmap's earlier decision gates also remain authoritative: recorded backend/protocol/event-loop/control/recovery decisions before implementation; toolkit evidence for AT-SPI, IME, RTL, large text, reduced motion and measured resource/frame behavior before lock-in; and a named distro/kernel/GPU/driver/topology/protocol/fallback matrix before hardware claims. Acceptance of delivery units 002, 003, 004 and 006, upgrade recovery and benchmark artifacts is required before 1.0. Public extensions additionally require reviewed capability use cases, API compatibility/permission UI and broker containment; extensions remain post-v1 unless explicitly promoted.

### Deliberately excluded later work

This is not a rolling-main release. Features and fixes after `d65e35f2` are absent unless explicitly identified above as causal fixture or candidate-version tooling changes. In particular, this base does not include #931 (`cba3cdbd`), the record-free fresh-account proof and strict old-image clock policy, or #987 (`7a623e10`), the historical shell-state evidence work. Do not attribute subsequent app-grid, clock/input/IME, installed-session, notification, portal, variant, rendering/driver or other follow-on repairs to this beta merely because they land on `main` or pass elsewhere. Qualification must judge this branch's actual installed binaries. Releasing this limited scope does not resolve those later issues or the broader #577 release work.

## Target configurations

- TunaOS Marlin, Arch-based bootc, x86_64: intended image target, subject to exact-image qualification.
- Ubuntu 26.04, amd64: intended Debian-format package target, subject to clean installation and installed GTK control qualification.
- Debian 13 is not a supported claim here: it requires a packaged gtk4-layer-shell >= 1.1 backport and a separately built and qualified artifact.
- Other TunaOS variants require the per-image evidence or unsupported disposition described above; no blanket support or physical-hardware claim is made.

## Required qualification and publication operations

Apply the [release runbook](../release.md) to the authorized branch and retain the exact final commit and relevant green CI evidence. Complete `docs/reviews/v1.0.0-beta.3.md` with actual comparison evidence, not placeholders, before a release build. A passing historical published-image lane is not a substitute for the new candidate's strict installed gates.

Before tagging, build and qualify the explicitly versioned pre-tag candidate: require complete version agreement, package contents/dependency closure, clean installation and real session controls, retaining package hashes, dependency receipts and exact source/image provenance. After those gates and review pass, build from the clean tagged checkout and verify the same source/version contract. Capture and inspect same-tag installed demonstration media and render its release media index. Publish only as a GitHub prerelease with the notes, actual package SHA-256, package artifact, media index and required media attached. Record actual tag, CI, qualification and publication receipts when those operations occur; none is represented as completed here.
