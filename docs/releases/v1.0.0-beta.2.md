# Tuna Desktop 1.0.0-beta.2

Second prerelease of Tuna Desktop: a Wayland desktop built on Smithay with a GTK 4 shell, aiming to match GNOME 51 as shipped in TunaOS Marlin. Package versions: Debian `1.0.0~beta.2`, Arch `1.0.0beta.2`; `--version` reports `1.0.0-beta.2`. This is a beta. It does not claim the [v1 gates](../v1.md) or the [roadmap release gates](../roadmap.md#global-decision-gates). Beta scope is set by [ADR 0008](../adr/0008-v1-beta-track-and-release-scope.md).

## Changes

Covers `main` from `v1.0.0-beta.1` (`d28578e`, 2026-10-15) to the tagged commit.

### Window management and input
- GNOME Multitasking preferences honored end to end: fixed workspace count, workspaces on primary only, edge tiling, current-workspace-only switching (P-WM-08) (#828).
- GNOME focus policy preferences (focus mode, auto-raise, raise on click, mouse-button modifier) (#816); accelerator grab and release flags (#708).
- Mouse, touchpad, trackball and pointing-stick device policies, including the acceleration profile (#810, #814).
- Input-source MRU, per-window sources and remembered Num Lock (#825); popup release and Num Lock keymap races fixed (#833); IME engine properties kept across engine switches (#826).
- Escape cancels a client drag, as Mutter's drag grab does (#675).

### Accessibility
- GNOME 51 screen magnifier as a live compositor render transform (P-A11Y-03) (#835), with zoom and tracking for captures (#629).
- Pointer accessibility aids: hover click with chooser and pie timer, simulated secondary click (#551).
- Genuine Orca native keyboard monitoring and grabs (#453); the session-owned reader retires before the session ends (#837).

### Shell, animations and settings
- App grid animations: folder zoom, launch zoom, page curve, arrows, reflow, page dots and swipe settle (#516, #829).
- Desktop transitions: lock curtain, unlock-dialog curtain drag, wallpaper crossfade, hot-corner ripples, startup and monitor change (#513, #830).
- Panel menus open with GNOME 51's BoxPointer rise and close/fade like GNOME, including OSDs (#811, #822).
- Night Light matches gsd 51's Color surface, smoothing and local zone (#815); DisplayConfig PowerSaveMode with Mutter 51 semantics (#818); bounded GNOME 51 brightness contract on native connectors (#706).
- Administrative lockdown policy engine and its shell consumers (#604, #821).
- Per-app notification preferences and lock-screen privacy (#559).
- SVG backgrounds rendered through a bounded native helper (#458).
- WWAN, location and CUPS printers Settings panels (partial, #605, #606).

### Session and system integration
- The Tuna session starts the GNOME 51 settings daemon plugins (#820).
- The graphical session starts without waiting for the shell or dbus-tools and exports `XDG_SESSION_TYPE=wayland` (#691, #699).
- Upgrade path: a narrow legacy transition that preserves user settings and login access (#780); the one-release roost compatibility layer is removed (#775).

### Performance
- Demand-driven compositor main loop (#678); shells get window updates only when they change, occluded windows wait for the hidden beat, and only client-damaged regions repaint (#696); damage-tracked repaints on the nested backend (#761).
- Shell: cairo drawing when OpenGL is a software rasterizer (#693); bounded overview chrome buffers (#719).
- Calibrated GNOME-relative regression budgets (#547) and bounded numeric performance diagnostics (#794, #799).

### Packaging, release and CI
- Arch PKGBUILD tracks the release tag (#689); prerelease packages accepted by the installed-runtime checks (#687, #697); staging modes protected across install implementations.
- Published `marlin:tuna` qualified through the real greeter login nightly (#273, #813).
- `try-tuna-desktop` one-liner (#741).
- CI: per-PR proof-lane selection (#683), overlapped proofs and seeded caches (#721), least-privilege tokens (#758), RustSec advisory gate (#759, #766, #767, #769).
- Toolchain kept current, most recently nightly-2026-10-20.

Open v1 gates (`docs/v1.md`), all unchecked for this beta:
- Not every tracked capability passes (rows above).
- Known gaps remain open (`[GNOME 51 gap]` issues).
- Daily work without any GNOME fallback is not yet proven.
- Responsiveness beating GNOME 51 on identical hardware is not yet shown across the board.
- Resource use matching GNOME 51 is not met: Tuna still uses more CPU than GNOME 51. That is the open v1 performance gate ([#503](https://github.com/tuna-os/tuna-desktop/issues/503)).
- The shipped Marlin image flavor is not yet qualified end to end on hardware (install, boot, real-greeter login, qualification run). The nightly VM lane logs in through the published image's GDM (#813); that is not hardware qualification.
- Release safety nets (recovery without data loss, proven upgrade path) are not yet proven. The upgrade mechanisms are recorded in `docs/legacy-upgrade.md`, with native qualification gaps listed there.
- Not every TunaOS variant ships a qualified Tuna flavor.
- The public v1 checklist is not yet one click from the front page.

Performance gate status:
- The Marlin performance-sample budget gate (#547) is not reproducible yet ([#782](https://github.com/tuna-os/tuna-desktop/issues/782)). Its failures exceeded the CPU budgets: notifications/desktop 3.58 vs 3.25, typing/desktop 1.80 vs 1.75, workspaces/desktop 1.39 vs 1.35 (run 39274768751, an older package). The notification ratio's mean per pair sits right at its budget, so the result of a median of three pairs is close to a coin flip.
- The nightly perf lane measured nothing from 2026-10-22 because the thread diagnostics stalled the GNOME sessions. The fix and the CPU-gap attribution are in open draft PR [#838](https://github.com/tuna-os/tuna-desktop/pull/838), not in this beta. Its identified fix (one read fence per frame in the vendored Smithay, which cuts llvmpipe wakeups) is not implemented yet.
- No new paired CPU figures are claimed for this beta. The last published pair is in the [beta.1 notes](v1.0.0-beta.1.md#known-limitations) (idle CPU 1.41% vs 0.14%); later compositor work (#678, #696) narrowed the gap but did not close it (`docs/perf/`).
- GPU and total-power comparisons stay waived for v1 (owner decision 2026-10-13).

Also:
- No physical-hardware qualification for any target.
- Visual review: `docs/reviews/v1.0.0-beta.2.md`. The baseline and frame gaps from beta.1 (#672) remain.

## Supported configurations
- TunaOS Marlin (Arch-based bootc), x86_64, via the `marlin:tuna` image.
- Ubuntu 26.04 (amd64), `.deb` package. Debian 13 is not supported yet: it needs a packaged gtk4-layer-shell >= 1.1 backport and a separately qualified artifact. Neither target has physical-hardware qualification.
