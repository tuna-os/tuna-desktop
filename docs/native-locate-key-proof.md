# Configured locate-pointer journey

`G-LOCATE-POINTER` in `scripts/tuna-gtk-shell-proof` changes the live `org.gnome.mutter locate-pointer-key` setting through the actual GTK settings publisher. The native Xvfb journey configures `Control_R`, requires a right Ctrl tap to increment the compositor's ripple count and rendered-frame counter at the pointer, and waits for the effect to finish. Left Ctrl, disabled locate-pointer, empty and unknown keysyms, a modifier chord, and a pointer button during the tap must leave both counters unchanged. The original key and enable setting are restored. Per-case compositor snapshots are collected beside the positive `locate-pointer.json` receipt.

The journey requires an installed Mutter schema (`mutter-common` in CI). When that schema lacks the newer key, `tuna-locate-schema.py` copies its installed XML into this proof's private schema directory and adds only a string `locate-pointer-key` with default `Control_L`. It preserves the other schemas in that document, original keys/defaults/ranges/aliases and referenced enum/flags definitions. Missing or ambiguous XML, a compiled/XML key-set mismatch, unresolved definitions, or a changed compiled key type/default/range are fatal. `schemas/locate-schema-provenance.json` records the original contract, XML hashes and whether this test-only extension was used; it is not evidence that the host shipped the newer key.

The source tests include an actual GLib compile/lookup of a constrained enum/range fixture. They do not build or launch the desktop. Native journey qualification requires the root CI run and its source/binary manifest. Active XKB keymap remapping is not exercised by this addition; it does not claim new keymap-remap or direct ripple-pixel qualification.
