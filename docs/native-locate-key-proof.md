# Configured locate-pointer journey

`G-LOCATE-POINTER` in `scripts/tuna-gtk-shell-proof` changes the live `org.gnome.mutter locate-pointer-key` setting through the actual GTK settings publisher. The native Xvfb journey configures `Control_R`, requires a right Ctrl tap to increment the compositor's ripple count and rendered-frame counter at the pointer, and waits for the effect to finish. Left Ctrl, disabled locate-pointer, empty and unknown keysyms, a modifier chord, and a pointer button during the tap must leave both counters unchanged. The original key and enable setting are restored. Per-case compositor snapshots are collected beside the positive `locate-pointer.json` receipt.

The journey requires an installed Mutter schema (`mutter-common` in CI). When that schema lacks the newer key, `tuna-locate-schema.py` copies its installed XML into this proof's private schema directory and adds only a string `locate-pointer-key` with default `Control_L`. It preserves the other schemas in that document, original keys/defaults/ranges/aliases and referenced enum/flags definitions. Missing or ambiguous XML, a compiled/XML key-set mismatch, unresolved definitions, or a changed compiled key type/default/range are fatal. `schemas/locate-schema-provenance.json` records the original contract, XML hashes and whether this test-only extension was used; it is not evidence that the host shipped the newer key.

The source tests include an actual GLib compile/lookup of a constrained enum/range fixture. They do not build or launch the desktop. Native journey qualification requires the root CI run and its source/binary manifest. The journey also configures a single US source and applies `ctrl:swap_lwin_lctl` live through `xkb-options`. Fixed physical XTEST keycodes 37 (left Ctrl) and 133 (left Super) are verified against the unchanged host keymap. The same physical Ctrl first ripples under the baseline map and then stops doing so under the swapped compositor map; physical Super then ripples instead. This confirms the configured keysym follows the applied compositor map without asking xdotool to resolve the new symbol. A Ctrl held across successful remap and a remapped key held across disable/re-enable must not ripple on release. All source/options/key/enable settings and physical held keys are restored on normal completion and the owned exit cleanup path. Existing physical Super overview behavior is dismissed before later journey stages.

Production invalidation remembers only successfully applied layout/variant/options. An identical successful application preserves the armed tap; a different successful application clears it. A failed keyboard map apply does not update that identity. Named compositor regressions `locate_map_change_cancels_held_tap_and_repeat` and `locate_unchanged_successful_map_preserves_held_tap` run in CI. Holding a modifier through the native journey's delay does not prove auto-repeat delivery; the repeated-press state regression is separate. Source/argument/GLib checks do not qualify the native journey or direct ripple pixels; those require CI evidence.
