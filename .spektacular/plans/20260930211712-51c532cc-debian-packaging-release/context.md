## Testing Strategy

Unit tests cover tag parsing and the version fallback rule (valid tags, missing or
garbage input), since every stamp flows through that one rule. Integration tests
run each built binary with `--version` and assert the output matches the stamped
version, proving the metadata-binaries agreement by construction. A package-level
test builds the artifact and inspects it: control fields present and consistent,
all four binaries plus the session entry in their installed locations,
executable bits set.

These slot into the existing gates: `cargo test --workspace` for the Rust tests,
`shellcheck` for the release script, and a new CI package-build step that fails
the run on packaging rot. Spec success metrics map directly: install-without-
compiler becomes the package-contents test plus a clean-install check; visible
version becomes the `--version` agreement tests; one-pass release becomes the
checklist-driven script itself.

Deliberate gaps: no clean-VM install test in CI (runner scope; documented as a
manual release-checklist step), no upgrade/rollback journey yet (rollback is a
later slice per the spec's non-goals).
