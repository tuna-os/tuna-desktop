# Shell keyboard access

> Derived from project rust-wayland-desktop (spektacular), spec/plan 20260929180654-154da51a-keyboard-access. See the project-level record for the full feature.

The Roost shell is now fully keyboard-operable: Tab and the arrows
move a visible accent ring across the panel strip, dock, popup
menus, and overview results; Enter activates whatever is focused;
Escape unwinds popups back to where you were and then closes the
overview onto your window. A new keymap document lists every
shortcut in one place.

## What changed in this repo

- `crates/shell-host/src/keyboard.rs`: nine navigation actions
  (arrows, Tab/Shift+Tab, F6, Super+D, Alt+F1) resolved
  keysym-first with keycode-tracked modifiers and queued from
  `on_key`.
- `crates/shell-host/src/panel.rs`: `ShellFocus` cursor with
  Panel/Dock/Popup/Overview regions, a bounded return stack, and
  settle-after-every-change; closed-overview Enter activates the
  focused stop; split Escape; overview hit cache behind the result
  cursor; rings painted from the focus-carrying paint keys; dock
  surface to `OnDemand` interactivity.
- `crates/shell-host/src/popup.rs`: `toggle` shared with keyboard
  activation; `tile_row_rect` inverse for row rings.
- `crates/shell-host/src/watcher.rs`: `menu_row_rect` inverse for
  indicator row rings.
- `crates/shell-host/src/overview.rs`: `draw_result_focus` accent
  border on the focused result row.
- `docs/keymap.md`: the single shell-plus-compositor chord
  reference, with the collision rule.
- 43 new tests: vocabulary, movement, activation, rings sampled
  from buffers, Escape unwind, trap fallback, live intent
  park/restore, and the scripted key-only run.

## Why

The shell is the daily touchpoint of the session; pointer-only
operation excludes keyboard-driven users and fails the GNOME
parity bar. Shell-local navigation (no compositor round-trip, no
wire change) keeps it fast while leaving every window chord
exactly where it was.
