# Session lock in rust-wayland-desktop

Idle sessions now blank and lock behind a compositor
surface; manual lock from the shell; unlock through the
login authentication path with silent failures.

> Derived from project rust-wayland-desktop (plan store), spec/plan 20260929180627-9e6f4a0d-session-lock. See the project-level record for the full feature.

## What changed in this repo

- New session-lock module plus unlock mediation reusing
  login auth (`compositor/src/lock.rs`, `unlock.rs`).
- Runtime wiring: idle accumulator, exclusive surface,
  flag-only snapshots (`runtime.rs`, `control.rs`).
- Control protocol 0.5 to 0.6: trailing locked flag and
  Lock command (`shell-control-schema`).
- Shell trigger and locked display (`shell-host`
  control, popup, panel, tiles).

## Why

Lock state must survive shell crashes, so it lives in
the compositor; auth must not fork, so it reuses login.
