# Session lock

## What was built

Roost sessions lock: an idle timeout or a shell trigger
raises a compositor-owned lock surface hiding every
window, title, and notification, and only the login
authentication path lowers it again. The locked flag
lives in the compositor, so shell restarts cannot clear
it; snapshots carry the flag without content; wrong
credentials stay locked silently.

## Why it matters

An unlocked idle session shows everything to anyone
walking by. With the lock in the compositor and auth
through the existing greetd path, Roost meets the basic
session-security bar without a second credential system.

## Deviations from the plan

The control protocol moved 0.5 to 0.6 for the trailing
locked flag and Lock command — wire-incompatible by
design, both peers shipping from this workspace.
