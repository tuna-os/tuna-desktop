# Keyboard access for the Roost shell

## What was built

Every Roost shell action now has a keyboard equivalent with visible
focus. The shell keeps one keyboard cursor across four regions —
panel strip (clock, tiles, indicator cells), dock slots, open popup
rows, and overview result rows — moved by Tab/Shift+Tab, arrows, F6,
Super+D, and Alt+F1, with an accent focus ring painted on every
focused stop. Enter activates through the same calls the pointer
uses (popups toggle, dock slots launch/switch, menu rows fire,
overview rows activate); Escape splits in two, closing popups back
to the parked shell focus first and dismissing the overview onto
the previously focused window second. A bounded return stack plus
settle-after-every-change keeps focus off closed or emptied
surfaces. `docs/keymap.md` documents every shell and compositor
chord in one place, and a scripted key-only run (calendar, dock
launch, indicator activation) proves the headline flows through
`on_key` injection.

## Why it matters

Keyboard-driven users get a shell that never traps focus and always
shows where it is — a daily-driver requirement carried over from
GNOME — while the structural collision rule (shell chords stay off
the compositor's window keys, pinned by tests on both sides) keeps
window management untouched.

## Deviations from the plan

None in behavior. Test hygiene deviation, recorded in the plan:
shell tests never fire Gio-backed calendar rows (the format/weekday
toggles write shared desktop state); row activation end to end is
proven by the in-memory power lock row instead.
