# Multi-monitor shell (2026-09-30)

## What was built

Roost now tracks every connected output in a compositor-owned
inventory — name, size, position, and primary flag per output —
instead of assuming a single display. The shell paints one panel
per output from that inventory (primary keeps the interactive
surface with presses and popups; the rest mirror the strip),
anchors the single dock to the primary output and rebinds it on
primary switches, and crops the wallpaper per output size with a
bounded per-size cache. A new `Outputs` control message (protocol
0.7) publishes the inventory to the shell on change and to every
newly connected shell; the compositor arranges each layer surface
against the output it is bound to. Removing an output preserves
every window: floating windows shift size-preserved into the
surviving slice and derived layouts re-resolve against the new
primary after failover, and the output's protocol global is
un-advertised so clients see the hotplug live.

## Why it matters

Docking a laptop or plugging in a second monitor now yields a
shell that follows the displays — panel, dock, and wallpaper
where they belong on every output — instead of stranding windows
on a vanished output or requiring a session restart. This is the
multi-monitor slice of the modern-GNOME-alternative goal: the
session behaves like a real multi-head desktop while staying on
the single-inventory architecture the spec requires.

## Deviations from the plan

- The plan assumed a per-output window list to re-map on
  removal; none exists (windows live in workspaces with no output
  affinity), so migration is geometric — same outcome, no new
  associations.
- Derived-layout re-resolution split into its own post-failover
  step after finding that re-applying before failover sizes
  windows for the dying primary.
- Chose a new `Outputs` message over extending `Snapshot` to
  avoid touching the revision/delta machinery; empty inventories
  are never sent.
- Entries gained auto-tiled global positions (needed for correct
  multi-output placement); render still presents primary only
  (single nested window), with per-output correctness proven at
  the arrange/crop/cache level and virtual-output tests.
- Shell presses and popups stay primary-only (noted gap).
