## Overview

Roost gains a safe way to extend the shell without rebuilding it: small extension scripts that add bar cells, dock badges, and indicator reactions. A bad or hostile script gets disabled with a visible note instead of taking the session down. Extension authors get the GNOME-extensions equivalent; users get customization without opaque binaries.

## Requirements

- [x] **Bar cells from scripts**
  Users can install an extension script that contributes a bar cell with text or an icon and a press action that runs.
- [x] **Dock badges from scripts**
  Users can see dock badges contributed by extension scripts that show the current value and update visibly whenever that value changes.
- [x] **Indicator reactions from scripts**
  Users can see a script's contributed output change on screen whenever an indicator it watches changes state.
- [x] **Sandboxed execution**
  The system must run scripts with no filesystem, network, or process access except through the shell-provided API.
- [x] **Crash-safe extensions**
  Users can keep working when a script fails or hangs: the system disables it with a visible note and never takes the shell down.
- [x] **Hot reload**
  Users can add, change, or remove a script and see the shell update without restarting the session.

## Constraints

- The solution must keep all script execution off the paint and event paths; no script code may run on the frame path.
- The solution must expose an allowlist-only API; anything not explicitly exposed must be inaccessible to scripts.
- The solution must load scripts as plain text from one user directory and must never execute binaries.
- The solution must not drop or delay keystrokes while loading, running, or reloading scripts.
- The solution must not give scripts access to window content or input injection.
- The solution must bound every script call so a hanging script is disabled with a visible note within two seconds.

## Acceptance Criteria

- [x] **Sample cell ships**
  A sample extension adding a bar cell ships with docs and works on a clean session.
- [x] **Sample badge and reaction work**
  Sample extensions contributing a dock badge and an indicator reaction update visibly on a clean session.
- [x] **Malicious script contained**
  A script attempting filesystem, network, or spawn access is denied and disabled; the shell stays up.
- [x] **Bad script disables cleanly**
  A script with a syntax error or infinite loop is disabled with a visible note within two seconds.
- [x] **Reload applies**
  Editing an installed script updates its cell without restart.

## Technical Approach

- Decided direction the planner may adapt: Rhai engine with a hand-built API module (bar cells, bus queries, notices).
- Suggested sandboxing shape: allowlist-by-construction per Constraints (register no filesystem, network, or process modules), proven by a hostile battery in tests.
- Suggested reliability shape: per-call timeouts and error capture, plus file watching for hot reload.

## Success Metrics

- Sample extension cell renders and reacts for real authors on clean sessions.
- No script failure or escape takes a session down in practice.
- Authors iterate on scripts with every edit applied and no restarts.
