# Feature: 20260929180654-154da51a-keyboard-access

## Overview

Every Roost shell action gains a keyboard equivalent with visible
focus: bar tiles, dock icons, popups, and menus all operate without
a pointer, and the keymap is documented in one place.

## Requirements

- [x] **Full keyboard operation**
  Every pointer action on bar, dock, popups, and menus has a
  keyboard equivalent.
- [x] **Visible focus**
  Keyboard focus in shell surfaces is always visibly indicated.
- [x] **Documented keymap**
  The shell keymap is documented in a single discoverable place.
- [x] **No keyboard traps**
  Focus never gets stuck in a shell surface; Escape always returns
  to the previously focused window.

## Constraints

- New bindings must not collide with the compositor's existing
  window-management keys.
- Focus indication reuses the existing accent and paint style.

## Acceptance Criteria

- [x] **Pointer-free session**
  A scripted key-only run opens the calendar, launches an app from
  the dock, and opens an indicator menu.
- [x] **Focus always visible**
  Every focused shell element paints its focus ring, sampled from
  surface buffers in test.
- [x] **Escape unwedges**
  From any open popup or menu, Escape returns focus to the
  previously focused window.

## Technical Approach

Decided direction the planner may adapt: extend the existing
keyboard feed with shell-focus routing, focus rings in the paint
passes, and a keymap document as the single reference.

## Success Metrics

- Key-only scripted run completes the three flows in a behavioural
  test.
- No open shell surface lacks a focus ring, asserted by paint
  test.

## Non-Goals

- Screen reader (AT-SPI) bridge: separate future work.
- Key rebinding UI.
- Sticky keys and other accessX features.
