# Feature: 20260929180627-9e6f4a0d-session-lock

## Overview

Roost locks idle sessions behind an unlock screen: idle detection
blanks and locks the session, and the user returns through the
same authentication the greeter uses. Unattended machines stop
being open doors.

## Requirements

- [x] **Idle locks the session**
  An idle session blanks and locks itself after the configured
  timeout.
- [x] **Manual lock works**
  Users can lock the session immediately from the shell.
- [x] **Unlock uses session auth**
  Unlocking authenticates through the same path as session login;
  wrong credentials stay locked with no hint about what failed.
- [x] **Lock survives shell restarts**
  A shell crash or restart while locked stays locked.

## Constraints

- Locked state lives in the compositor, never the restartable
  shell: a shell crash cannot unlock.
- The lock screen shows no window content, titles, or
  notifications while engaged.
- Authentication reuses the greeter auth path; no parallel
  credential handling.

## Acceptance Criteria

- [x] **Timeout locks**
  With a short idle timeout set, an untouched session shows the
  lock screen and hides all windows.
- [x] **Password unlocks**
  Entering the correct password dismisses the lock and restores
  the session intact.
- [x] **Wrong password stays locked**
  Three wrong passwords keep the session locked with no window
  content leaked.
- [x] **Restart stays locked**
  Restarting the shell process while locked keeps the lock screen
  up.

## Technical Approach

Decided direction the planner may adapt: compositor-owned lock
flag with an overlay-style exclusive surface, idle tracking from
input timestamps, and unlock mediated by the existing greetd
session path.

## Success Metrics

- Idle timeout produces the lock surface in a behavioural test.
- Wrong-credential unlock attempts never reveal content, asserted
  by test.

## Non-Goals

- Fingerprint or smartcard unlock factors.
- Remote lock administration.
- Per-user lock customization themes.
