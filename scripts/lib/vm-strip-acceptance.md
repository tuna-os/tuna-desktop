# Installed strip acceptance foundation

This opt-in VM lane runs on the final pristine Marlin boot. It retains all
existing startup, tour and lifecycle gates. CI binds original same-run package
executable hashes and the fixture sources to a read of the immutable final image.
Runtime core executable hashes must match that image receipt. The receipt is CI
package/image provenance; it does not qualify signed release installation.

Three genuine GTK Wayland clients use nonce application IDs, custom painted
headers and resize grips. Actual Gdk Toplevel requests are driven by QMP mouse
input. The observer requires original process/start/boot identities, genuine
configure/allocation/paint observations, stable native geometry, and actual
framebuffer color controls. Eight endpoint captures cover floating, strip enable,
width preset, navigation, continuous pointer width, pointer reorder, actual VT
cancellation, and independent floating geometry restoration. Endpoint captures
are not kernel presentation or completed-action latency measurements.

This source does not yet establish the full issue #582 acceptance: stacked rows,
all cross-workspace/output behavior, offscreen drag edge scrolling, and installed
restart coverage remain separate obligations. It also does not qualify #587.
No service is spoofed and no desired geometry is written into the compositor.
The existing count-only input fixture remains the default.

The fixture supervisor records uncertain launch ownership before spawning. A
lost acknowledgment cannot become successful cleanup. Exact client and launcher
PID identities are checked before pidfd signaling; unconfirmed retirement fails
the phase. This does not claim arbitrary descendant/process-group retirement.
The installed compositor snapshot does not expose each window's kernel PID;
nonce application identities plus the independently owned real GTK process are
retained, with native_window_kernel_pid_join_qualified explicitly false.

The product pointer leaf must be reconciled with this proof foundation before a
native positive run. The base 375a2244 carries transport support but lacks the
new product pointer implementation. No source unit test substitutes an actual
installed pass. Local checks use synthetic observations and owned host children;
all image builds, GTK/Gdk and VM execution remain CI-only and require review.
