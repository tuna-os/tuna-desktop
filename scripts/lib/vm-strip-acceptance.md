# Installed strip acceptance foundation

This opt-in VM lane runs on the final pristine Marlin boot. It retains all
existing startup, tour and lifecycle gates. CI binds original same-run package
executable hashes and the fixture sources to a read of the immutable final image.
Runtime core executable hashes must match that image receipt. The receipt is CI
package/image provenance; it does not qualify signed release installation.

Three genuine GTK Wayland clients use nonce application IDs, custom painted
headers and resize grips. Actual Gdk Toplevel requests are driven by QMP mouse
input. The observer requires original process/start/boot identities, genuine
configure/allocation/paint observations, stable native geometry, and actual
framebuffer color controls. Eight endpoint captures cover floating, strip enable,
width preset, navigation, continuous pointer width, pointer reorder, actual VT
cancellation, and independent floating geometry restoration. Strip columns
follow stacking, so the focus click leaves Alpha last; after strip enable, actual
Super+Shift+arrow column moves carry it, one observed slot at a time, until Beta
is its right neighbor. Endpoint captures
are not kernel presentation or completed-action latency measurements.

This source does not yet establish the full issue #582 acceptance: stacked rows,
all cross-workspace/output behavior, offscreen drag edge scrolling, and installed
restart coverage remain separate obligations. It also does not qualify #587.
No service is spoofed and no desired geometry is written into the compositor.
The existing count-only input fixture remains the default.

The fixture supervisor records uncertain launch ownership before spawning. A
lost acknowledgment cannot become successful cleanup. Exact client and launcher
PID identities are checked before pidfd signaling; unconfirmed retirement fails
the phase. This does not claim arbitrary descendant/process-group retirement.
The installed compositor snapshot does not expose each window's kernel PID;
nonce application identities plus the independently owned real GTK process are
retained, with native_window_kernel_pid_join_qualified explicitly false.

The product pointer leaf must be reconciled with this proof foundation before a
native positive run. The base 375a2244 carries transport support but lacks the
new product pointer implementation. No source unit test substitutes an actual
installed pass. Local checks use synthetic observations and owned host children;
all image builds, GTK/Gdk and VM execution remain CI-only and require review.

## Explicit stationary edge mode

`--strip-edge` requires the existing exact image receipt and final tour boot.
It selects a fixed four-actor GTK mode and exact root-admitted argv; the default
three-actor and count-only clients remain available. This is one owned launch,
not a second attempt over the persistent owner record. All original eight input,
VT, restore and cleanup controls still run. The stationary phase follows the
nonvacuous VT control so it cannot hide Beta before that control runs.

One actual title gesture moves into the right band, followed by no more host
input until the initiating release. An observer with no input capability samples
original window/process/image identity, real pointer coordinates, unchanged GTK
input counters, viewport advances and distinct actual render counts. It allows
an explicitly typed live strip_animating state during demand. It refuses a target
already visible initially, early/stale terminal, missing roles, remapping, pointer
or input changes, viewport lag/regression and expired absolute deadlines.

Completion requires observed live movement over multiple actual frames, a fully
visible formerly offscreen Delta, a genuine settled state and a terminal render
newer than the last live observation. Three equal terminal observations may refer
to that same actual terminal frame; they do not invent three renders. Both PNG
and PPM are independently decoded and color checked before the actual insertion
and initiating release are accepted. Their acquisitions remain distinct and do
not qualify kernel presentation latency. Sparse half-second observations are
not a recording of every frame.

The new phase is bounded by min(remaining original120second phase,60seconds), with
128 observations maximum and unchanged post-read/post-validation deadline checks.
No original deadline is raised. This requires composition with the reviewed edge
product before actual CI execution. Source/synthetic controls do not prove GTK,
native DRM pixels, full issue582/587, installed restart or multioutput behavior.
